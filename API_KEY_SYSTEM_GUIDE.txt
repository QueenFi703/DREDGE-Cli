SYSTEM OVERVIEW
===============

This complete system provides:

1. API KEY GENERATION
   - Secure random key generation (256-bit)
   - Unique key IDs for tracking
   - Format: orion_key_xxxxxxxx

2. SECURE STORAGE
   - SHA-256 hashing with salt (bcrypt-like format)
   - Constant-time verification (timing attack resistant)
   - JSON file persistence (or database)

3. FASTAPI INTEGRATION
   - Dependency injection for clean code
   - Middleware for automatic request tracking
   - Decorator for per-route protection

4. AUTHENTICATION & AUTHORIZATION
   - x-api-key header verification
   - Role-based access (modes)
   - Rate limiting by tier

5. USAGE TRACKING
   - Per-request tracking
   - Endpoint breakdown
   - Monthly usage reports
   - Rate limit enforcement

API KEY GENERATION & FORMAT
============================

Format: orion_key_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

Example: orion_key_7kQzPmN9vL2xJwRsT5fGhYuI8jKpOqAb

Key Components:
- Prefix: orion_key_
- Random: 32 characters (URL-safe base64)
- Total: 40+ characters
- Entropy: 256 bits

Generation Process:
1. Generate 32 random bytes
2. Encode to URL-safe base64
3. Create key ID from first 12 chars
4. Hash with SHA-256 + random salt
5. Return plaintext (user stores) + hash (database)


AUTHENTICATION METHODS
======================

Header-Based (Recommended):
──────────────────────────
curl -H "x-api-key: orion_key_xxx" https://api.example.com/invoke

Query Parameter (Not Recommended - not URL encoded):
────────────────────────────────────────────────────
curl https://api.example.com/invoke?key=orion_key_xxx

Authorization Bearer (Alternative):
─────────────────────────────────────
curl -H "Authorization: Bearer orion_key_xxx" https://api.example.com/invoke


AUTHENTICATION FLOWS
====================

Flow 1: Simple Request
──────────────────────
Client → Request with x-api-key header
  ↓
Middleware extracts API key
  ↓
APIKeyStore.validate_key(plaintext_key)
  ↓
Hash key with extracted salt
  ↓
Compare hashes (constant-time)
  ↓
If match → Return metadata, else → Reject
  ↓
Route handler processes request
  ↓
Middleware records usage
  ↓
Response returned with rate limit headers


Flow 2: Rate Limiting
─────────────────────
verify_rate_limit dependency called
  ↓
Check: requests_this_month < requests_limit
  ↓
If exceeded → Return 429 Too Many Requests
  ↓
If OK → Allow request to proceed
  ↓
Update: requests_this_month += 1
  ↓
Calculate: usage_percent = (requests_this_month / limit) * 100


Flow 3: Admin Operations
────────────────────────
Admin sends request with admin key
  ↓
Validate key (same as above)
  ↓
Check: mode == KeyMode.FULL_ACCESS
  ↓
If not → Return 403 Forbidden
  ↓
If yes → Execute admin operation
  ↓
Example operations:
- Create new key (returns plaintext once)
- Revoke existing key
- List all keys
- View statistics

API KEY MODES
=============

READ_ONLY
  Allowed endpoints:
  - GET /health
  - GET /usage
  - GET /admin/stats (if admin)

INVOKE_ONLY
  Allowed endpoints:
  - POST /invoke (main inference)
  - GET /health

FULL_ACCESS
  All endpoints:
  - Everything READ_ONLY
  - Everything INVOKE_ONLY
  - All admin endpoints


ENDPOINT REFERENCE
==================

PUBLIC ENDPOINTS (No authentication)
────────────────────────────────────

GET /
  API information and documentation
  Response: {service, version, auth, docs}

GET /health
  System health check
  Optional: x-api-key for usage tracking
  Response: {status, timestamp}

GET /docs
  Swagger UI documentation
  Allows testing endpoints


PROTECTED ENDPOINTS (x-api-key required)
─────────────────────────────────────────

POST /invoke (Mode: INVOKE_ONLY or FULL_ACCESS)
  Main inference endpoint
  Required: x-api-key header
  Body: {input, mode, context}
  Response: {request_id, status, result, usage}

GET /usage (Mode: READ_ONLY or FULL_ACCESS)
  Get your current usage for this month
  Required: x-api-key header
  Response: Usage statistics and reset date


ADMIN ENDPOINTS (Mode: FULL_ACCESS required)
──────────────────────────────────────────────

POST /admin/keys/create
  Create new API key
  Body: {name, tier, mode, environment}
  Response: {status, key, key_id, metadata}
  NOTE: Plaintext key only returned once!

GET /admin/keys/list
  List all API keys (without plaintext values)
  Response: List of all keys with metadata

POST /admin/keys/{key_id}/revoke
  Revoke/disable an API key
  Path param: key_id
  Response: {status, message}

GET /admin/stats
  View system-wide statistics
  Response: {total_keys, active_keys, requests, by_tier}

GET /admin/usage/{key_id}
  View detailed usage for a specific key
  Path param: key_id
  Response: Detailed usage report


RESPONSE HEADERS
================

X-RateLimit-Limit
  Total requests available this month

X-RateLimit-Remaining
  Requests remaining this month

X-RateLimit-Tier
  Your subscription tier

Example:
  X-RateLimit-Limit: 10000
  X-RateLimit-Remaining: 9850
  X-RateLimit-Tier: pro


ERROR HANDLING
==============

401 Unauthorized
  Missing or invalid API key
  Response: {"status": "error", "detail": "Missing API key"}

403 Forbidden
  Key doesn't have required permissions
  Response: {"status": "error", "detail": "Insufficient permissions"}

429 Too Many Requests
  Rate limit exceeded
  Header: Retry-After: 3600
  Response: {"status": "error", "detail": "Rate limit exceeded"}

400 Bad Request
  Invalid request body or parameters
  Response: {"status": "error", "detail": "Invalid JSON body"}

404 Not Found
  Resource not found
  Response: {"status": "error", "detail": "Key not found"}

TROUBLESHOOTING
===============

Issue: "Missing API key"
Solution: Add x-api-key header to request

Issue: "Invalid API key"
Solution: Check key format (orion_key_xxx)
Solution: Check key hasn't been revoked

Issue: "429 Too Many Requests"
Solution: Check usage with GET /usage
Solution: Upgrade to higher tier
Solution: Wait until monthly reset (1st of month)

Issue: "403 Forbidden"
Solution: Use admin key for /admin/* endpoints
Solution: Check key mode matches endpoint requirements

Issue: Keys not persisting after restart
Solution: Check ./data/orion_api_keys.json exists
Solution: Ensure write permissions to ./data directory
