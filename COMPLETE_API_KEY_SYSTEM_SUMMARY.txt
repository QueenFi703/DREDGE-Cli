SECURITY ARCHITECTURE
======================

Key Generation:
  1. Generate 32 random bytes
  2. Encode to URL-safe base64
  3. Create display key ID (first 12 chars)
  4. Hash with SHA-256 + random 16-byte salt
  5. Return format: $2$<salt>$<hash>

Key Storage:
  - Only hash stored in database (never plaintext)
  - Plaintext returned once to user
  - Salt embedded in hash for verification
  - Constant-time comparison prevents timing attacks

Key Validation Flow:
  1. Extract API key from x-api-key header
  2. Iterate over stored hashes
  3. Compute hash with extracted salt
  4. Compare using hmac.compare_digest()
  5. Return metadata if match, None otherwise
  6. Update last_used_at timestamp


FASTAPI INTEGRATION
====================

Method 1: Direct Dependency Injection (Recommended)
───────────────────────────────────────────────────

from fastapi_auth_middleware import APIKeyDependencies

deps = APIKeyDependencies(key_store, tracker)

@app.post("/invoke")
async def invoke(key: APIKeyMetadata = Depends(deps.verify_rate_limit)):
    # key is already validated and rate limit checked
    return {"usage": key.to_dict()}


Method 2: Middleware for Automatic Tracking
────────────────────────────────────────────

from fastapi_auth_middleware import APIKeyMiddleware

app.add_middleware(APIKeyMiddleware, key_store=key_store, tracker=tracker)

# Now all endpoints automatically track usage


Method 3: Decorator Pattern
──────────────────────────

@app.post("/endpoint")
@require_api_key(required_mode=KeyMode.INVOKE_ONLY)
async def endpoint(request: Request):
    key = request.scope["api_key_metadata"]
    return {"key_id": key.key_id}


API ENDPOINTS (Complete Reference)
===================================

PUBLIC (No auth required):
──────────────────────────

GET /
  ├─ Returns API information
  └─ Response: {service, version, auth, docs}

GET /health
  ├─ System health check
  ├─ Optional: x-api-key for tracking
  └─ Response: {status, timestamp, tracked}

GET /docs
  └─ Swagger UI documentation


PROTECTED (x-api-key required):
───────────────────────────────

POST /invoke (Mode: INVOKE_ONLY or FULL_ACCESS)
  ├─ Main inference endpoint
  ├─ Request: {input, mode, context}
  └─ Response: {request_id, status, result, usage}
  └─ Rate limited based on tier

GET /usage (Any mode)
  ├─ Get current monthly usage
  └─ Response: {tier, requests_this_month, requests_limit, reset_date}


ADMIN (Mode: FULL_ACCESS required):
─────────────────────────────────────

POST /admin/keys/create
  ├─ Create new API key
  ├─ Body: {name, tier, mode, environment}
  └─ Response: {status, key, key_id}

GET /admin/keys/list
  ├─ List all API keys
  └─ Response: List of key metadata

POST /admin/keys/{key_id}/revoke
  ├─ Revoke/disable API key
  └─ Response: {status, message}

GET /admin/stats
  ├─ View system statistics
  └─ Response: {total_keys, active_keys, requests}

GET /admin/usage/{key_id}
  ├─ View usage for specific key
  └─ Response: Detailed statistics


AUTHENTICATION HEADER
=====================

Format:
  x-api-key: orion_key_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

Example:
  x-api-key: orion_key_7kQzPmN9vL2xJwRsT5fGhYuI8jKpOqAb

Validation:
  1. Extracts key from header
  2. Validates against stored hash
  3. Checks if active and not expired
  4. Returns metadata or rejects


RESPONSE HEADERS (Rate Limiting)
================================

X-RateLimit-Limit
  Total requests available this month
  Example: 10000

X-RateLimit-Remaining
  Requests remaining this month
  Example: 9850

X-RateLimit-Tier
  Your subscription tier
  Example: pro

Complete example:
  HTTP/1.1 200 OK
  X-RateLimit-Limit: 10000
  X-RateLimit-Remaining: 9850
  X-RateLimit-Tier: pro
  
  {"result": "..."}

USAGE TRACKING
==============

Automatic per-request tracking:
  - Endpoint called
  - Request method (GET/POST/etc)
  - Response status code
  - Response time (ms)
  - Client IP address
  - User agent
  - Tokens used (if applicable)

Monthly statistics:
  - Total requests this month
  - Breakdown by endpoint
  - Average response time
  - Peak usage time

Reset date:
  - 1st of each month (UTC)


ERROR HANDLING
==============

401 Unauthorized
  Missing or invalid API key
  Solution: Add valid x-api-key header

403 Forbidden
  Insufficient permissions
  Solution: Use key with proper mode/role

429 Too Many Requests
  Rate limit exceeded for this month
  Solution: Upgrade tier or wait for reset

400 Bad Request
  Invalid request body
  Solution: Check JSON format

404 Not Found
  Resource doesn't exist
  Solution: Check key_id or endpoint
