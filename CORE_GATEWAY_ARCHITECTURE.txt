🎯 ARCHITECTURE OVERVIEW
=========================

What is the Core Gateway?

  A single FastAPI/ASGI application that serves as the execution spine
  for the entire DREDGE platform. All functionality is provided through
  a modular, extensible adapter system.

Design Pattern: Unified ASGI Spine with Modular Adapters

✅ FEATURES
===========

Single Entry Point:
  ✅ One ASGI application (core_gateway.py)
  ✅ One FastAPI instance
  ✅ One Uvicorn server
  ✅ Clean deployment model

Modular Adapters:
  ✅ Studio Adapter: Web UI and dashboards
  ✅ Auth Adapter: API key management
  ✅ Health Adapter: System monitoring
  ✅ Admin Adapter: Administrative operations

Adapter Management:
  ✅ AdapterRegistry: Central adapter registration
  ✅ Enable/disable adapters dynamically
  ✅ List adapter status and capabilities
  ✅ Graceful error handling per adapter

Resilience:
  ✅ If one adapter fails, others continue
  ✅ Adapter failures logged but don't crash gateway
  ✅ Fallback to minimal app if needed
  ✅ Health checks work independently

Extensibility:
  ✅ Easy to add new adapters
  ✅ Clear interface for adapter creation
  ✅ Adapters are independent modules
  ✅ No tight coupling between adapters

🚀 HOW IT WORKS
================

Step 1: Start Core Gateway
  python core_gateway.py
  
  Output:
    DREDGE CORE GATEWAY - ASGI Application Spine
    Mounting adapters...
    [Mount] Studio adapter mounted
    [Mount] Auth adapter mounted
    [Mount] Health adapter mounted
    [Mount] Admin adapter mounted
    Gateway Status:
      - Service: DREDGE Core Gateway
      - Adapters: 4 enabled

Step 2: Core Gateway starts FastAPI app
  - Registers all adapters in AdapterRegistry
  - Mounts each adapter router via include_router()
  - Ready to receive requests on port 8000

Step 3: Requests routed to correct adapter
  GET /studio/dashboard → Studio Adapter
  POST /auth/keys/create → Auth Adapter
  GET /health/detailed → Health Adapter
  GET /admin/info → Admin Adapter

Step 4: Each adapter processes independently
  - Adapters don't depend on each other
  - Failure in one adapter doesn't affect others
  - Each adapter has its own routes and logic

🔄 ADAPTER LIFECYCLE
====================

Registration:
  adapter_registry.register(
    name="Studio",
    enabled=True,
    description="DREDGE Studio Web UI"
  )

Mounting:
  router = create_studio_adapter()
  app.include_router(router)

Execution:
  User request → Route matching → Adapter handling

Error Handling:
  ├─ Adapter fails to load → Logged, marked disabled
  ├─ Adapter fails during request → HTTP error response
  └─ Core gateway continues serving other adapters

  ✅ Clear ownership of concept

📝 CREATING NEW ADAPTERS
==========================

Template for new adapter:

  def create_my_adapter():
      from fastapi import APIRouter
      
      router = APIRouter(prefix="/myfeature", tags=["MyFeature"])
      
      @router.get("/status")
      async def status():
          return {"status": "operational", "adapter": "myfeature"}
      
      return router


To add to core gateway:

  # In mount_adapters() function in core_gateway.py:
  
  try:
      my_router = create_my_adapter()
      app.include_router(my_router)
      adapter_registry.register("MyFeature", enabled=True, 
                               description="My new feature")
  except Exception as e:
      logger.warning(f"[Mount] MyFeature adapter failed: {e}")
      adapter_registry.register("MyFeature", enabled=False, 
                               description="My feature (failed)")
