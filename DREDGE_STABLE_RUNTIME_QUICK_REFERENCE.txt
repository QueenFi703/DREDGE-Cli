🎯 YOUR PROBLEM & SOLUTION
============================

Your Operating Environment:
  • Windows Host (non-critical)
  • WSL2 VM (can crash)
  • Docker Desktop (should survive crashes)
  • Vercel CI/CD (needs isolation)
  • Single-machine hybrid kernel

Your Requirements:
  ✅ WSL never crashes my containers
  ✅ Dockers survives terminal resets
  ✅ Vercel builds run in isolated lanes
  ✅ Gateway becomes deterministic under deployment

Our Solution: 5-Layer Resilient Topology
  Layer 1: Host Kernel (Windows) - Non-critical
  Layer 2: WSL2 Isolation - Resilient VM
  Layer 3: Docker Engine - Service-based survival
  Layer 4: DREDGE Gateway - Volume-backed state
  Layer 5: Vercel Build Lanes - Isolated containers

🚀 DEPLOYMENT (5 MINUTES)
===========================

✅ GUARANTEES
==============

Guarantee 1: WSL Never Crashes Your Containers
───────────────────────────────────────────────
How it works:
  1. Docker daemon runs in Hyper-V (survives WSL)
  2. Containers have restart: always policy
  3. Gateway state in volume (survives crash)
  4. On restart: read checkpoint, recover state

Test it:
  wsl --shutdown
  # Wait 30 seconds
  curl http://localhost:9000/health  # Should respond

Timeline:
  ├─ T+0s: WSL crashes
  ├─ T+1s: Docker restarts gateway
  ├─ T+5s: State recovered from volume
  ├─ T+10s: Service ready
  └─ T+30s: Fully recovered


Guarantee 2: Docker Survives Terminal Resets
──────────────────────────────────────────────
How it works:
  1. Containers run in daemon mode (detached)
  2. Docker service is independent Windows service
  3. Terminal crash doesn't affect daemon
  4. Containers keep running

Test it:
  docker-compose -f docker-compose.stable-topology.yml up -d
  # Press Ctrl+C
  docker ps  # All containers still running


Guarantee 3: Vercel Builds Run in Isolated Lanes
─────────────────────────────────────────────────
How it works:
  1. Sequential processing (one build at a time)
  2. Per-build container with unique ID
  3. Isolated network (no cross-build communication)
  4. Isolated volume (no artifact sharing)
  5. No shared state

Test it:
  POST /build/submit (5 times)
  # Observe sequential processing in /queue/status


Guarantee 4: Gateway Is Deterministic
──────────────────────────────────────
How it works:
  1. Version pinning with SHA256 digest
  2. State synchronized before deploy
  3. Deterministic startup sequence
  4. Blue-green deployment
  5. Rollback window

Test it:
  # Deploy new version
  # Observe /state/status shows same sessions/queue
  # All requests still in queue, no loss

📋 TROUBLESHOOTING
====================

Issue: Containers not starting
Solution:
  1. Check Docker is running
  2. Verify volumes exist: ./volumes/{state,logs,artifacts}
  3. Check ports: netstat -an | find "9000" "9001"
  4. View logs: docker-compose logs

Issue: Gateway crashes after startup
Solution:
  1. Check watchdog: curl http://localhost:9000/watchdog/status
  2. Check state: docker volume ls | grep dredge
  3. View logs: docker logs dredge-gateway
  4. Restart: docker restart dredge-gateway

Issue: Builds not processing
Solution:
  1. Check queue: curl http://localhost:9001/queue/status
  2. View build logs: docker logs dredge-build-queue
  3. Check network: docker network ls | grep build-lanes
  4. Check isolation: docker ps (look for build-* containers)

Issue: State not recovering
Solution:
  1. Check checkpoint: ls ./volumes/state/
  2. Verify permissions: chmod 777 ./volumes/state
  3. Check manifest: cat ./volumes/state/manifest.json
  4. View recovery log: cat ./volumes/state/recovery.log

🎓 KEY CONCEPTS
=================

Determinism
  Same code + same state = same behavior
  Achieved via:
  ├─ SHA256 image digests (exact image)
  ├─ State checkpoints (exact state)
  ├─ Deterministic startup (ordered init)
  └─ Blue-green deployments (atomic switch)

Resilience
  System survives failures at multiple layers
  Achieved via:
  ├─ Volume persistence (survives crash)
  ├─ Auto-restart policies (auto-recovery)
  ├─ Health checks (detect failures)
  ├─ Watchdog monitoring (respond to failures)
  └─ Layered isolation (failures contained)

Isolation
  Failures in one area don't affect others
  Achieved via:
  ├─ Named networks (separate networks)
  ├─ Named volumes (separate storage)
  ├─ Per-build containers (per-request isolation)
  ├─ Resource limits (prevent exhaustion)
  └─ Health checks (detect degradation)
