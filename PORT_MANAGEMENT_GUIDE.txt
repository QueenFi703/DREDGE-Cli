RUNNING MULTIPLE SERVICES

Option B: Docker Compose (Production)
──────────────────────────────────────

version: '3.8'
services:
  orion:
    build: ./orion
    ports:
      - "8080:8080"
  
  dredge:
    build: ./dredge-cli-repo
    ports:
      - "3001:3001"
  
  advanced:
    build: ./advanced
    ports:
      - "8000:8000"
  
  auth-gateway:
    build: .
    ports:
      - "9000:9000"
    depends_on:
      - orion
      - dredge
      - advanced
    environment:
      - ORION_URL=http://orion:8080
      - DREDGE_URL=http://dredge:3001
      - ADVANCED_URL=http://advanced:8000


Option C: Systemd Services (Linux)
──────────────────────────────────

/etc/systemd/system/orion.service
[Unit]
Description=Orion Gateway
After=network.target

[Service]
Type=simple
User=app
WorkingDirectory=/app
ExecStart=/usr/bin/python3 orion_gateway_authenticated.py
Restart=on-failure

[Install]
WantedBy=multi-user.target

# Enable and start
sudo systemctl enable orion.service
sudo systemctl start orion.service


FIREWALL CONFIGURATION
======================

Production Setup - Expose Only 9000:

iptables -A INPUT -p tcp --dport 9000 -j ACCEPT
iptables -A INPUT -p tcp --dport 8080 -j REJECT  # Internal only
iptables -A INPUT -p tcp --dport 3001 -j REJECT  # Internal only
iptables -A INPUT -p tcp --dport 8000 -j REJECT  # Internal only

Or in nginx:
upstream orion_gateway {
    server 127.0.0.1:9000;
}

server {
    listen 80;
    server_name api.example.com;
    
    location / {
        proxy_pass http://orion_gateway;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}

TROUBLESHOOTING
===============

Issue: "Service not found"
Solution: Check service is running on correct port
Example: curl http://127.0.0.1:8080/health

Issue: "Connection refused on port 9000"
Solution: Start gateway: python unified_auth_gateway.py

Issue: "401 Unauthorized"
Solution: Add x-api-key header
Example: -H "x-api-key: orion_key_xxx"

Issue: "429 Too Many Requests"
Solution: Check usage: curl -H "x-api-key: KEY" http://127.0.0.1:9000/usage

Issue: Backend service returns 502
Solution: Check backend is running on expected port
