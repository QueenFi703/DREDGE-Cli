API ENDPOINTS (webMCP on Port 3000)
============================================================================

Core:
  GET  /                      - webMCP UI (HTML)
  GET  /api/health            - Health check
  GET  /api/status            - System status
  GET  /api/docs              - OpenAPI docs

Agents:
  GET  /api/agents            - List all agents
  GET  /api/agents/{id}       - Get agent details
  POST /api/agents/{id}/task  - Emit task to agent

Tasks:
  POST /api/tasks/{id}/complete - Mark task complete

Events:
  GET  /api/events            - Get event log
  WS   /ws/events             - WebSocket stream

============================================================================
EVENT FLOW EXAMPLE
============================================================================

Step-by-step task execution:

1. USER ACTION
   - Selects "analysis-agent" from UI dropdown
   - Sets task type: "analyze"
   - Sets payload: {"query":"test"}
   - Clicks "Emit Task"

2. REQUEST SENT
   POST /api/agents/analysis-agent/task
   {
     "task_type": "analyze",
     "payload": {"query": "test"}
   }

3. ORCHESTRATOR REGISTERS
   - Emits: task_emitted event
   - Sets agent status: busy
   - Updates: last_activity timestamp
   - Increments: total_tasks

4. EVENT BROADCAST
   - WebSocket sends event to all clients
   - UI updates in real-time
   - Event added to log

5. AGENT PROCESSES (simulation)
   - Processing task...
   - Working...

6. TASK COMPLETION
   POST /api/tasks/task-123/complete
   {
     "agent_id": "analysis-agent",
     "result": {"status": "success"}
   }

7. COMPLETION LOGGED
   - Emits: task_completed event
   - Updates agent status: idle
   - Increments: completed_tasks
   - Updates statistics

8. UI REFLECTS CHANGES
   - Event stream shows completion
   - Counters updated
   - Agent status changes to idle

============================================================================
ORCHESTRATION PATTERNS
============================================================================

Pattern 1: Sequential Pipeline
  Input → analysis → planning → execution → Output
  Blocks: Agents work in sequence

Pattern 2: Parallel Processing
  Input → [research, analysis] (parallel) → planning → Output
  Concurrency: Multiple agents simultaneously

Pattern 3: Feedback Loop
  Input → analyze → plan → execute → evaluate → [loop if needed]
  Iteration: Refinement cycles

Pattern 4: Hierarchical
  Boss agent delegates to workers, collects results
  Hierarchy: Multi-level coordination
