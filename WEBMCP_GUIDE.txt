Version: 1.0.0
Status: Production Ready

============================================================================
WHAT IS webMCP?
============================================================================

webMCP is a sophisticated web-based implementation of the Model Context Protocol
that turns DREDGE's orchestration architecture into a powerful agentic system.

It combines:
  ✓ DREDGE orchestration concepts (events, state transitions, agents)
  ✓ MCP protocol for extensibility
  ✓ Real-time event streaming via WebSocket
  ✓ Multi-agent coordination
  ✓ Polished web UI with gradient design
  ✓ REST API for programmatic access

============================================================================
EVENT FLOW
============================================================================

1. Client emits task to agent:
   POST /api/agents/analysis-agent/task
   {
     "task_type": "analyze",
     "payload": {"data": "..."}
   }

2. Orchestrator registers event:
   Event: task_emitted
   Data: {agent_id, task_id, task_type, payload}

3. Agent processes task (async)
   - Sets status to "busy"
   - Updates last_activity

4. Client marks task complete:
   POST /api/tasks/{task_id}/complete
   {
     "agent_id": "analysis-agent",
     "result": {...}
   }

5. Orchestrator registers completion:
   Event: task_completed
   Data: {agent_id, task_id, result}

6. UI updates in real-time via WebSocket

============================================================================

Example orchestration definition:

{
  "graph": {
    "entry": "analysis-agent",
    "edges": [
      {
        "from": "analysis-agent",
        "to": "planning-agent",
        "state_delta": {"analysis_complete": true}
      },
      {
        "from": "planning-agent",
        "to": "execution-agent",
        "state_delta": {"plan_ready": true}
      }
    ]
  }
}

This defines the workflow:
  Analysis → Planning → Execution

With automatic state transitions.

============================================================================
AGENT ORCHESTRATION PATTERNS
============================================================================

Pattern 1: Sequential (Analysis → Planning → Execution)
  1. analysis-agent analyzes input
  2. planning-agent creates plan based on analysis
  3. execution-agent executes plan
  4. Results flow back

Pattern 2: Parallel (Multiple agents simultaneously)
  1. research-agent gathers information
  2. analysis-agent analyzes patterns
  3. planning-agent creates strategy (parallel)
  4. Results merged and executed

Pattern 3: Feedback Loop (Iterative refinement)
  1. analysis-agent produces initial result
  2. planning-agent refines
  3. execution-agent tests
  4. Results feedback to analysis-agent
  5. Repeat until optimal

Pattern 4: Hierarchical (Agent delegation)
  1. planning-agent receives high-level goal
  2. Delegates subtasks to other agents
  3. Coordinates results
  4. Reports back

============================================================================
STATE MANAGEMENT
============================================================================

System State:
  active_agents: Number of registered agents
  total_tasks: Total tasks emitted
  completed_tasks: Successfully completed tasks
  failed_tasks: Failed tasks
  system_status: "online" | "offline" | "degraded"

Agent State:
  id: Agent identifier
  type: Agent type/role
  status: "idle" | "busy"
  tasks_completed: Count of completed tasks
  created_at: Agent registration time
  last_activity: Last activity timestamp

Event Log:
  timestamp: ISO timestamp
  type: Event type
  data: Event payload
  max_size: 1000 events (rolling)

============================================================================
WEBSOCKET EVENT STREAM
============================================================================

Connect:
  const ws = new WebSocket('ws://127.0.0.1:3000/ws/events');

Message Format:
  {
    "timestamp": "2026-01-15T10:30:45.123Z",
    "type": "task_emitted|task_completed|agent_registered",
    "data": {...}
  }

Events:
  - agent_registered: New agent registered
  - task_emitted: Task sent to agent
  - task_completed: Task finished
  - state_updated: State changed

Real-time Updates:
  UI automatically updates on each event
  No polling required
  Low latency (<100ms typical)

============================================================================
INTEGRATION WITH OTHER SYSTEMS
============================================================================

With MCP Server (Port 3002):
  1. webMCP registers agents in MCP registry
  2. MCP provides tool definitions
  3. Agents implement MCP tools
  4. External systems use MCP protocol

With DREDGE Server (Port 8001):
  1. Tasks routed to DREDGE execution layer
  2. Resource allocation from DREDGE
  3. Telemetry collected by DREDGE
  4. Results reported back to webMCP

With Gateway (Port 8080):
  1. API requests routed through gateway
  2. Authentication at gateway level
  3. Rate limiting at gateway
  4. Monitoring/logging at gateway

EXTENDING webMCP
============================================================================

Adding Custom Agents:

```python
orchestrator.register_agent(
    "custom-agent",
    "custom_type",
    {"timeout": 60, "config_key": "value"}
)
```

Creating Agent Behaviors:

```python
async def custom_agent_handler(task_id, task_type, payload):
    # Process task
    result = await process(payload)
    
    # Mark complete
    orchestrator.complete_task("custom-agent", task_id, result)
```

Implementing Custom Tools:

```python
# In MCP server
@mcp_app.post("/tools/custom-tool")
async def custom_tool(request: Request):
    body = await request.json()
    # Tool implementation
    return {"result": "..."}
```

Issue: Events not updating in UI
Fix: Check browser console, verify WebSocket connection

Issue: High memory usage
Fix: Clear old events, reduce event log size

Issue: Slow performance
Fix: Check system resources, profile agent tasks
